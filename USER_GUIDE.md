# NaviCare User Guide

This guide shows you how to run NaviCare on your own machine, how to use it
as a patient, a care coordinator, or an admin, and how its triage agent
decides how urgent a message is.

> **NaviCare is not a medical device and does not give medical advice.**
> It does not diagnose, prescribe, or make medical decisions. It is an open
> source project for learning, research, and building on. Do not use it with
> real patients without your own clinical review, legal review, and
> regulatory approval. In an emergency, call your local emergency number.

## 1. What NaviCare is

NaviCare is a patient portal with an AI "Patient Navigator" chat. A patient
types a message, and NaviCare decides what kind of help they need:

| The patient says something like… | NaviCare sends it to… | What happens |
|---|---|---|
| "I'm having chest pain and can't breathe" | **Emergency check** (no AI) | A fixed message telling them to get emergency care now |
| "I've had a mild cough for two days" | **Triage Agent** | Asks how urgent it is, maybe one follow-up question |
| "What is an MRI?" | **Information Agent** | Answers from a curated knowledge base, with sources |
| "I need to see a dermatologist" | **Appointment Agent** | Offers slots, books only after the patient confirms |
| "Remind me about my appointment tomorrow" | **Follow-Up Agent** | Creates a reminder |
| "I want to talk to a person" | **Escalation** | Puts the conversation in the staff queue |

The main feature is **triage**: working out how urgently a patient's symptoms
may need attention. The rest of this section and the next explain how that
works.

### The core rule

> **The AI helps understand and communicate. It never has the final say on
> patient safety.**

In practice this means:

- Every message is checked for emergency warning signs **before** the AI is
  called. If one matches, the AI is skipped completely.
- Fixed safety rules can **raise** urgency above what the AI decided, but
  nothing can **lower** it.
- If the AI is down, slow, or returns something malformed, the emergency
  check still runs.

## 2. How triage works

Each patient message goes through these steps:

```
Patient message
      │
      ▼
① Emergency pre-check (pattern matching, no AI)
      │── match ──► Fixed emergency message. Stop.
      ▼
② Is a staff member handling this chat?
      │── yes ────► "A care coordinator will reply." The AI stays out.
      ▼
③ Navigator Agent (AI) works out what the patient wants
      │
      ▼  symptom concern
④ Triage Agent (AI) rates urgency: routine / urgent / emergency / unknown
      │
      ▼
⑤ Safety rules check the message again and keep the HIGHER urgency
      │
      ▼
Reply shown to the patient, with a banner if urgent or emergency
```

### ① Emergency pre-check

Before any AI call, the raw message is checked against a list of emergency
patterns. The built-in ones live in
[`safety/baseline.py`](patient-navigator/backend/safety/baseline.py):

| Category | Example phrases |
|---|---|
| Heart / breathing | "chest pain", "can't breathe", "shortness of breath" |
| Stroke | "stroke", "face drooping", "slurred speech", "sudden numbness" |
| Bleeding / trauma | "severe bleeding", "can't stop bleeding", "unconscious" |
| Mental health crisis | "suicidal", "kill myself", "hurt myself", "overdose" |
| Seizure | "seizure", "passed out", "lost consciousness" |
| Allergic reaction | "anaphylaxis", allergic reaction with throat swelling |

If any of these match, the patient immediately gets this fixed message
(written by a person, never generated by the AI):

> I'm concerned that what you're describing may need urgent medical
> attention. Please seek immediate care — contact your local emergency
> number or go to the nearest emergency department. If you are in immediate
> danger, please do not wait for a reply here.

Emergencies **never** go into the staff queue. A patient with chest pain is
told to get care now, not to wait for a coordinator.

### ④ The Triage Agent

If the message is about symptoms but isn't an emergency, the Triage Agent
looks at the message and the conversation so far, and returns:

| Field | Meaning |
|---|---|
| `urgency` | `routine`, `urgent`, `emergency`, or `unknown` |
| `warning_signs` | Worrying signs the patient mentioned |
| `needs_clarification` / `clarifying_question` | At most **one** follow-up question per turn, only if it's needed to judge urgency |
| `recommended_action` | e.g. `SEEK_EMERGENCY_CARE`, `SEEK_PROMPT_MEDICAL_CARE`, `ROUTINE_FOLLOWUP` |
| `confidence` | Used internally only. **Never shown to the patient**, so it can't be mistaken for a medical probability |
| `response` | The text shown to the patient |

The agent is told never to diagnose ("you have X"), never to falsely
reassure ("that's nothing serious"), and to lean toward higher urgency when
unsure. Its output is checked field by field
([`agents/triage/schemas.py`](patient-navigator/backend/agents/triage/schemas.py));
anything malformed is thrown away and replaced with a safe fallback.

### ⑤ Safety rules have the last word

After the Triage Agent answers, the message is checked against the safety
rules again
([`safety/service.py`](patient-navigator/backend/safety/service.py)).
The two results are compared and **the more severe one wins**:

| Triage Agent says | Safety rule says | Final result |
|---|---|---|
| routine | nothing matched | routine (AI's reply is used) |
| routine | urgent ("getting worse") | **urgent**, with the fixed urgent message |
| urgent | emergency ("chest pain") | **emergency**, with the fixed emergency message |
| emergency | routine | **emergency** (rules never lower urgency) |

When a rule raises the urgency, the AI's text is replaced by the rule's
fixed message.

The default **urgent** rules cover persistent or high fever, worsening
symptoms, and severe pain. Their fixed message asks the patient to see a
professional today, and to treat it as an emergency if things get worse.

### What the patient sees

- **Emergency** → red banner: *"Seek emergency care now"*
- **Urgent** → banner: *"Prompt medical attention recommended"*
- **Routine** → normal reply, no banner

### When things go wrong

- **AI is down or slow:** the patient gets "temporarily unavailable, please
  try again", but the emergency check still runs on their message.
- **Three failures in a row** (configurable): the conversation is
  automatically handed to the human staff queue.

## 3. Setting it up

### What you need

- Python 3.12+ (Django 6 won't install on older versions)
- Node.js 20.19+ or 22.12+
- PostgreSQL (optional — SQLite is used if you don't set `DATABASE_URL`)
- An Anthropic API key, for the AI agents. Without one, the emergency check
  and safety rules still work, but AI replies show a "temporarily
  unavailable" message.

### Backend

```bash
cd patient-navigator/backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Open `.env` and set at least:

```ini
SECRET_KEY=any-long-random-string
LLM_API_KEY=your-anthropic-api-key
LLM_MODEL=claude-sonnet-4-6
# Remove or comment out DATABASE_URL to use SQLite instead of Postgres
```

Then set up the database and sample data:

```bash
python manage.py migrate
python manage.py seed_safety_rules      # the triage safety rules (important!)
python manage.py seed_knowledge_base    # articles the Information Agent answers from
python manage.py seed_appointments      # sample providers and time slots
python manage.py createsuperuser        # your admin account
python manage.py runserver
```

The API runs at `http://localhost:8000`.

> Always run `seed_safety_rules`. If you skip it, the built-in emergency
> patterns still protect you, but the **urgent** rules (fever, worsening
> symptoms, severe pain) won't exist.

### Frontend

In a second terminal:

```bash
cd patient-navigator/frontend
npm install
cp .env.example .env     # sets VITE_API_BASE_URL=http://localhost:8000/api
npm run dev
```

Open `http://localhost:5173`.

### Reminders (optional)

To send follow-up reminders that are due, run this on a schedule (for
example with cron):

```bash
python manage.py process_reminders
```

### Useful settings in `.env`

| Setting | Default | What it does |
|---|---|---|
| `LLM_MODEL` | `claude-sonnet-4-6` | Which model the agents use |
| `MAX_AGENT_FAILURES_BEFORE_ESCALATION` | `3` | Failures in a row before a chat goes to staff |
| `KNOWLEDGE_MIN_SIMILARITY` | `0.15` | How close a knowledge base match must be; below this the Information Agent says "I don't have enough information" |
| `KNOWLEDGE_RETRIEVAL_TOP_K` | `3` | How many knowledge base passages to use per answer |
| `HIGH_ESCALATION_TARGET_MINUTES` | `15` | Response-time target shown to staff for high-priority escalations |
| `NORMAL_ESCALATION_TARGET_MINUTES` | `60` | Same, for normal priority |

## 4. Using it as a patient

1. **Register** at `/register`, then log in.
2. Fill in your **Profile** so the navigator has basic context.
3. On the **Dashboard**, type your question in the box and press start. A new
   conversation opens.
4. Chat normally. Examples to try:
   - *"I've had a mild cough for two days."* → triage, probably routine
   - *"My fever has lasted three days."* → triage, raised to **urgent** by a
     safety rule
   - *"I have chest pain."* → instant **emergency** message, no AI involved
   - *"What does fasting before a blood test mean?"* → answer with sources
   - *"I want to talk to a person."* → handed to a care coordinator
5. If the triage agent asks a follow-up question, answering it helps it judge
   urgency. It won't ask more than one question per turn.
6. Replies from a person show a **Care Support** label, so you always know
   whether you're talking to staff or the AI.
7. **Follow-ups** and **Notifications** show your reminders and updates.

You only ever see your own data. Other patients' conversations can't be
opened, even by guessing their ID.

## 5. Using it as a care coordinator

Care coordinators handle conversations the AI handed off. They are **not**
admins and can't see agent traces or metrics.

**To make someone a care coordinator:** have them register normally, then
log in to `http://localhost:8000/admin/` as the superuser, open their user,
tick **Staff status** (not Superuser status), and save.

**Working the queue** (`/care-support`):

1. Filter by status or show only conversations you've claimed.
2. **Claim** an escalation. Only one person can claim it; if someone beat
   you to it you'll see a conflict.
3. Read the **internal summary**, so the patient doesn't have to repeat
   themselves.
4. **Reply.** Your message appears in the patient's chat under "Care
   Support". While you own the conversation, the AI stays silent (the
   emergency check still runs on every patient message).
5. **Resolve** when you're done. Every action is recorded in an audit trail.

Things that land in the queue: patients asking for a person, requests NaviCare
can't handle (like changing a prescription), and repeated AI failures.
Emergencies never land here; they get the immediate-care message instead.

## 6. Using it as an admin

Superusers can do everything a care coordinator can, plus:

- **Agent Monitoring** (`/agent-monitoring`): request volume, success rate,
  escalations, average response time, a breakdown by agent, and failures by
  type.
- **Trace viewer**: every patient message gets a step-by-step trace (safety
  pre-check → navigator → triage, and so on) with timing and status. Traces
  deliberately **don't** store prompts, full messages, or the AI's
  reasoning.
- **Django admin** (`/admin/`): manage users, safety rules, and the
  knowledge base.

## 7. Customizing the triage safety rules

There are two layers of safety rules:

| Layer | Where | Who can change it | Can it be turned off? |
|---|---|---|---|
| **Built-in emergency patterns** | [`safety/baseline.py`](patient-navigator/backend/safety/baseline.py) | Developers (code change) | No. Always checked, even if the database is down |
| **Database rules** | `/admin/` → Safety rules | Superusers (or staff given the permission), no deploy needed | Yes, untick **Active** |

### Adding a rule in the admin

1. Go to `/admin/` → **Safety rules** → **Add**.
2. Fill in:
   - **Name:** e.g. `Severe dehydration`
   - **Category:** e.g. `General`
   - **Trigger:** a regular expression, matched case-insensitively, e.g.
     `\b(no urine|haven'?t peed)\b.*\b(day|hours)\b`
   - **Severity:** `emergency`, `urgent`, `routine`, or `informational`
   - **Response:** the exact fixed text the patient will see when this rule
     decides the outcome
3. Save. It applies to the next message.

Tips:

- Use `\b` around words so `stroke` doesn't match `heatstroke` by accident.
  Test your pattern on a site like regex101 before saving.
- A rule with an invalid regex is skipped and logged, not crashed on.
- Write responses in plain, calm language. Don't diagnose.
- Have a clinician review any rule you add before real use.

### Changing the built-in emergency patterns

Edit `EMERGENCY_PATTERN_GROUPS` in
[`safety/baseline.py`](patient-navigator/backend/safety/baseline.py). It's
the single source for the pre-check, the fail-safe check, and the seeded
database rules. Then rerun `python manage.py seed_safety_rules` and the
tests.

### Showing a specific emergency number

All patient-facing text says "your local emergency number", so it works in
any country. To show a specific number (like 911, 112 or 999), edit
`EMERGENCY_RESPONSE` in
[`safety/baseline.py`](patient-navigator/backend/safety/baseline.py),
`URGENT_RESPONSE` in
[`safety/rules.py`](patient-navigator/backend/safety/rules.py), and the chat
footer in
[`frontend/src/pages/Chat.jsx`](patient-navigator/frontend/src/pages/Chat.jsx).
Then rerun `python manage.py seed_safety_rules` so the database rules pick up
the new text.

## 8. Running the tests

```bash
cd patient-navigator/backend
python manage.py test
```

The full suite has 400+ tests and can take around 10 minutes. The tests cover triage output validation, the "rules never lower urgency"
guarantee, the emergency check running without any AI call, prompt
injection attempts, and patients being unable to see each other's data.

The routing tests use a mocked AI (no API key is needed), so they check that
messages are **routed and handled safely**, not how accurate a real model's
judgment is. The emergency tests use no mock at all, since that path never
calls the AI.

## 9. Troubleshooting

| Problem | Likely cause | Fix |
|---|---|---|
| Every reply says "The assistant is temporarily unavailable" | `LLM_API_KEY` is missing or wrong | Set it in `backend/.env` and restart the server |
| Emergency messages work but nothing else does | Same as above: the emergency check doesn't need the AI | Same as above |
| "I don't have enough information" for every health question | Knowledge base is empty | Run `python manage.py seed_knowledge_base` |
| "Fever for 3 days" isn't flagged urgent | Safety rules weren't seeded | Run `python manage.py seed_safety_rules` |
| No appointment slots | Sample appointments weren't seeded | Run `python manage.py seed_appointments` |
| Frontend can't reach the API / CORS error | URLs don't match | Check `VITE_API_BASE_URL` in `frontend/.env` and `CORS_ALLOWED_ORIGINS` in `backend/.env` |
| Database connection error on start | `DATABASE_URL` points to a Postgres that isn't running | Start Postgres, or remove `DATABASE_URL` to use SQLite |
| Can't see Care Support or Monitoring | Your account lacks the right role | Staff status for Care Support; Superuser for Monitoring |

## 10. Limits

- **Not a diagnosis tool.** Triage only estimates urgency. It never says what
  is causing symptoms.
- **Pattern matching has gaps.** The emergency patterns are a conservative
  starting point, not a full clinical triage protocol. Unusual wording,
  typos, or other languages may not match. The triage AI is told to lean
  toward higher urgency, but it can still be wrong.
- **English only** at the moment.
- **No real clinical systems.** There's no connection to medical records,
  pharmacies, or real appointment systems; appointments are sample data.
- **Not production-hardened.** If you deploy it anywhere real, you are
  responsible for clinical validation, privacy law (e.g. HIPAA, GDPR),
  security review, and hosting.
